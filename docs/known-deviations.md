# 已知偏差与诚实清单

规格是 `DEVELOPMENT.md`，这里是"实际做出来的东西和它不一样的地方"，以及为什么。
逐条核验表在 §24.1，本文不重复证据，只讲取舍。

## 与规格书的偏差

| # | 偏差 | 原因 | 影响 |

## 方法学上的局限（写进 §24.5，这里再列一遍）

1. 采样法会丢短于 `interval` 的窗口切换；
2. 窗口标题不等于意图（`code.exe` 三小时 ≠ 写了三小时代码）；
3. 全屏视频/游戏照样算前台应用时间，工具不猜你在干嘛；
4. 多显示器只有一个前台窗口，副屏活动不单独计时；
5. 空闲阈值（默认 5 分钟）是人为约定，不是真理；
6. 空闲延伸最多会让"刚回来的那几秒"算作空闲 —— 方向是刻意的：**宁可少算，不虚报**。

## 刻意"做重"的地方

- **空闲回填**：把"发现空闲"回溯到它真正的起点，顺手把"挂着窗口去吃饭"剔除。
  这是这个工具唯一的、也是最重要的差异化。
- **账本守恒**：所有桶加起来必须等于区间总长，差额只能落在「空闲」与「未记录」这两个
  明说的桶里 —— 没有"其它"这种黑盒，且由测试钉住。
- **自报可信度**：覆盖率、最大采样间隔、丢弃的异常采样数印在报告头部；
  覆盖率低的时候报告会直接说"先确认 tracker 一直在跑，再相信下面的数字"。
- **永不联网**：不是口号，是一条会 FAIL 的验收项（AST 扫 import 图）。
- **读坏了不写盘**：数据库损坏 / 版本不匹配时按空库打开，但原文件一个字节都不动。
- **报告只报账不打分**：没有效率分、没有红黄绿，见 ADR-0003。
