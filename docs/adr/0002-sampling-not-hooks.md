# ADR-0002：采样法，而不是窗口事件钩子

- 状态：已接受（2026-09-23）
- 相关：`DEVELOPMENT.md` §9（判定规则）、§24.5（方法学局限）

## 背景

要记录"你在用什么程序"，技术上主要有两条路：

1. **窗口事件钩子**：注册 `SetWinEventHook`（或轮询 `GetForegroundWindow` 的变体），
   窗口一切换就收到通知。精度到毫秒级的切换序列。
2. **定期采样**：每 N 秒问一次"现在前台是谁"，记一行。

钩子听起来明显更好 —— 直到你开始考虑它的代价：

- 事件回调要在消息循环里跑，意味着要建窗口、跑 `GetMessage` 循环，代码复杂度和崩溃面都上一个台阶；
- 挂钩子需要在自己的进程里长期持有回调，任何一处异常都可能静默丢掉事件，而**你无法察觉**；
- 要跨进程/跨会话完整工作，还得处理会话切换、UAC 提权窗口等边角；
- 最重要的是：它把"记录"和"被观察的窗口系统"绑得太紧，一个不稳定的钩子会让你**以为**记全了。

## 决策

**用采样法**：默认每 5 秒取一次前台窗口（进程名 + 标题）和"距上次键鼠输入的秒数"，写一行记录。
不用钩子、不装消息循环、不注册任何全局钩子。

关键在于：**丢掉精度之后，用空闲回填把诚实度补回来**（`DEVELOPMENT.md` §9.2/§9.3）。

- `idle_s` 是"距离上一次键鼠输入过了多久"，所以当我们看到"已空闲 130 秒"时，
  真正的空闲是从 `ts - 130s` 开始的；
- 于是 `[ts-130s, 下一次采样]` 整段被划成空闲 —— **"挂着窗口去吃饭"不会被算成工作**；
- 采样漏掉的那些"小于 5 秒的切换"落在被划走的那一段里，本来就该是空闲。

换句话说：**我们放弃了"精确到每次切换"，换来了"不会虚报"**。对这个工具来说后者才是命门。

## 后果

**正面**

- 常驻进程极简：一个 `while` + `time.sleep`，一次采样 P95 仅 **0.03ms**（实测量级），CPU 基本看不见；
- 抗崩溃：别的程序死掉、窗口系统异常、我们自己的某次调用失败，都只影响一条记录（`kind=error`），
  循环继续；
- 崩溃代价可控：进程被杀最多丢一个采样间隔；
- 零依赖：不需要消息循环、不需要额外的库；
- 可测：采样器接受注入的 provider 与时钟，核心逻辑在任何平台、任何 CI 上都能完整测。

**负面（写进 §24.5，不许藏）**

| 代价 | 说明 |
| --- | --- |
| 短于采样间隔的切换不计入 | 5 秒内的快速 Alt-Tab 会被抹平；`--interval 1` 可以缓解但磁盘翻 5 倍 |
| 采样间隔本身是近似的来源 | 报告头部的"最大采样间隔 / 覆盖率"就是给用户判断可信度用的 |
| 休眠/关机期间完全没有数据 | 记成「未记录」而不是猜成"空闲" —— 我们确实不知道那是人在发呆还是机器睡了 |
| 全屏视频与游戏照样算前台应用时间 | 工具不知道你在学习还是在摸鱼，也不打算猜（`--exclude` 交给用户） |

## 备选方案

- **`SetWinEventHook` 事件流**：精度最高，但代码复杂度、静默丢事件的风险、跨会话的边角都更差；
- **浏览器历史 / 应用日志分析**：只能看到一部分活动，且有"看历史"和"看屏幕"两种完全不同的隐私含义；
- **混合（钩子 + 采样兜底）**：M1 之后如果要更细的切换统计，可以考虑用采样做基线、钩子做可选增强，
  但**默认路径永远是采样**。
